# MQTT API

Backend-facing MQTT contract for the ISIC attendance reader firmware.

## Topic Prefix

All MQTT topics are device-scoped:

```text
<baseTopic>/<deviceId>/<topicSuffix>
```

- `baseTopic` comes from `mqtt.baseTopic` and defaults to `device`
- `deviceId` comes from `device.deviceId` and defaults to `ISIC-ESP8266-001`

Example:

```text
device/ISIC-ESP8266-001/attendance
```

## Backend -> Board

Publish these topics from backend services to control the board.

| Topic pattern | Payload | Purpose | Response |
|---|---|---|---|
| `<prefix>config/set` | full config JSON | Replace/update the full runtime config | none |
| `<prefix>config/set/<section>` | section JSON | Replace/update one config section | none |
| `<prefix>config/get` | empty payload | Request the full runtime config | `<prefix>config` |
| `<prefix>config/get/<section>` | empty payload | Request one config section | `<prefix>config/<section>` |
| `<prefix>health/request` | empty payload | Force an immediate health snapshot publish | `<prefix>health` |
| `<prefix>metrics/request` | empty payload | Force an immediate metrics snapshot publish | `<prefix>metrics` |
| `<prefix>ota/start` | empty payload | Trigger OTA manifest check and, if newer, OTA flow | OTA status topics below |

Supported config sections:

| Section | JSON object keys |
|---|---|
| `wifi` | `stationSsid`, `stationPassword`, optional `stationUsername` when built with Eduroam support, `stationConnectRetryDelayMs`, `stationConnectionTimeoutMs`, `stationFastReconnectIntervalMs`, `stationSlowReconnectIntervalMs`, `stationMaxFastConnectionAttempts`, `stationPowerSaveEnabled`, `stationHasEverConnected`, `accessPointSsidPrefix`, `accessPointPassword`, `accessPointModeTimeoutMs` |
| `mqtt` | `brokerAddress`, `port`, `username`, `password`, `baseTopic`, `keepAliveIntervalSec`, `reconnectMinIntervalMs`, `reconnectMaxIntervalMs` |
| `device` | `deviceId`, `locationId` |
| `pn532` | `spiSckPin`, `spiMisoPin`, `spiMosiPin`, `spiCsPin`, `irqPin`, `pollIntervalMs`, `readTimeoutMs`, `maxConsecutiveErrors`, `recoveryDelayMs` |
| `attendance` | `debounceIntervalMs`, `batchMaxSize`, `batchFlushIntervalMs`, `offlineBufferSize`, `offlineBufferFlushIntervalMs`, `batchingEnabled`, `offlineQueuePolicy` |
| `feedback` | `enabled`, `ledEnabled`, `ledPin`, `ledRedPin`, `ledGreenPin`, `ledBluePin`, `buzzerEnabled`, `buzzerPin`, `ledActiveHigh`, `beepFrequencyHz`, `successBlinkDurationMs`, `errorBlinkDurationMs` |
| `health` | `healthCheckIntervalMs`, `statusUpdateIntervalMs`, `metricsPublishIntervalMs`, `publishToMqtt` |
| `ota` | `enabled`, `serverUrl`, `username`, `password`, `timeoutMs`, `checkOnConnect` |
| `power` | `readerIdleTimeoutMs`, `modemSleepAfterMs`, `pn532SleepAfterMs`, `readerReadyHoldMs`, `burstWindowMs`, `burstScanCount`, `burstHoldMs`, `enableNfcWakeup`, `nfcWakeupPin`, `autoSleepEnabled`, `disableWiFiDuringSleep`, `pn532SleepBetweenScans`, `modemSleepOnMqttDisconnect`, `activityTypeMask` |

Notes:

- `config/set/#` accepts either a full config object or a single section object.
- `config/get/#` ignores payload contents.
- The firmware does not publish an explicit ack or error topic for `config/set`.
- Config payloads include credential fields such as Wi-Fi and MQTT passwords in plain JSON.

## Board -> Backend

Subscribe to these topics in backend services.

| Topic pattern | Payload | Retained | Produced when |
|---|---|---|---|
| `<prefix>attendance` | JSON array of attendance records | no | a batch is flushed online or an offline buffer is replayed |
| `<prefix>health` | JSON object with board health snapshot | yes | periodic publish or `health/request` |
| `<prefix>metrics` | JSON object with per-service metrics | yes | periodic publish or `metrics/request` |
| `<prefix>config` | full config JSON | no | response to `config/get` |
| `<prefix>config/<section>` | section config JSON | no | response to `config/get/<section>` |
| `<prefix>ota/update_available` | firmware version string | no | OTA check found a newer version |
| `<prefix>ota/progress` | integer percent as string, e.g. `"42"` | no | OTA download is in progress |
| `<prefix>ota/completed` | `"success"` | no | OTA download and update completed |
| `<prefix>ota/error` | string in format `error: <reason>` | no | OTA failed |

## Payload Examples

### Attendance

```json
[
  {
    "uid": "04A1B2C3D4",
    "ts": 1710000000000,
    "seq": 42
  }
]
```

Notes:

- `uid` is an uppercase hex string.
- `ts` is Unix time in milliseconds at serialization time.
- If system time is unavailable, `ts` is `0`.
- `seq` is an in-memory sequence counter generated by the firmware.

### Health

```json
{
  "device_id": "ISIC-ESP8266-001",
  "firmware": "1.0.3",
  "state": "healthy",
  "uptime_s": 1234,
  "cpu_freq": 80,
  "free_heap": 32768,
  "heap_state": "healthy",
  "heap_fragm": 12,
  "fragm_state": "healthy",
  "wifi_rssi": -61,
  "wifi_rssi_state": "healthy"
}
```

Note:

- Current implementation publishes `device_id` from the firmware default constant, not from the runtime `device.deviceId` config.

### Metrics

```json
{
  "ConfigService": {
    "state": "running"
  },
  "WiFiService": {
    "state": "running",
    "disconnect_count": 1
  },
  "MqttService": {
    "state": "running",
    "published": 25,
    "failed": 0,
    "received": 4,
    "reconnects": 2
  },
  "AttendanceService": {
    "state": "running",
    "cards_processed": 12,
    "cards_debounced": 3,
    "batches_sent": 12,
    "errors": 0
  }
}
```

Notes:

- The top-level keys are service names.
- The exact set of service objects depends on which components were registered with `HealthService`.

## Full Config Shape

The full payload returned on `<prefix>config` uses this top-level structure:

```json
{
  "magic": 1230190915,
  "version": 1,
  "wifi": {},
  "mqtt": {},
  "device": {},
  "pn532": {},
  "attendance": {},
  "feedback": {},
  "health": {},
  "ota": {},
  "power": {}
}
```
